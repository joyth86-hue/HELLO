# 音声（BGM・効果音）

## 元データ・取り込み方

BGMの元ファイルは、このアプリのリポジトリ直下の`/音楽`フォルダ（ユーザーが随時曲を置いていく作業用の置き場、`.gitignore`済みでリポジトリには含まれない）に置かれる。[characters.md](./characters.md)の`サンプル画像/`・[items.md](./items.md)の元画像フォルダと同様、**このフォルダの中身は消したり移動したりせず、実際に使う曲だけを選んで`public/audio/`へコピーして使う**（置かれた曲を全部自動的に取り込むわけではない）。

- コピー先：[public/audio/bgm/](../../public/audio/bgm/)（1画面1曲、ファイル名はローマ字化した曲名。例：「穏やかなとき.mp3」→`odayakana-toki.mp3`）
- どの曲をどの画面で使うかは、その都度ユーザーから指示を受けて決める。指示が無い曲はまだ用途未定として取り込まない
- 定数・プール定義は[lib/audio-tracks.ts](../../lib/audio-tracks.ts)にまとめている（画面側は個別にファイルパスをハードコードしない）

## 画面ごとのBGM割り当て

| 画面 | 曲 | 定数 |
| --- | --- | --- |
| ゲーム開始画面（タップして開始する） | はじまり | `START_BGM` |
| ホーム画面 | 穏やかなとき | `HOME_BGM` |
| ステージ選択画面 | 束の間 | `STAGE_SELECT_BGM` |
| ショップ（ガチャ）画面 | ドキドキ宝箱 | `SHOP_BGM` |
| 戦闘（S-1〜S-9、通常バトル） | ステージ番号で固定（下記） | `getNormalBattleBgmForStage(stage)` |
| 戦闘（S-10、ボス戦） | ボス戦用プールからランダム | `pickRandomBossBattleBgm()` |
| 戦闘結果：ボスを倒した | 小さな達成感 | `STAGE_CLEAR_BGM` |
| 戦闘結果：全滅した | 敗北を知る者たち | `DEFEAT_BGM` |

### 戦闘BGMの選び方（ユーザー確認済み）

- **通常バトル（S-1〜S-9）はステージ番号ごとに固定**：同じステージ内で毎回選び直すことはしない（`getNormalBattleBgmForStage(stage)` = `NORMAL_BATTLE_BGM_POOL[(stage-1) % プール数]`という決定的な割り当てで、同じステージなら毎回同じ曲になる）
- **ボス戦（S-10）だけはランダム**：ボス戦に入るたびに`BOSS_BATTLE_BGM_POOL`から`pickRandomBossBattleBgm()`でランダムに1つ選び直す
- 通常バトル用プール（6曲）：勇敢な戦士たち／天翔ける龍の閃き／月の世界／月光が照らす獣／荒野に吹く風／静かなる闘い1（個別に用途指定された曲を除いた「残りのファイル」）
- ボス戦用プール（2曲）：強敵現る／静かなる闘い2
- ステージクリア（ボス撃破）・全滅の結果画面では、それぞれ専用の曲に切り替わる（戦闘中の曲に戻ることはなく、画面を離れる＝ホームへ戻るまでそのまま鳴り続ける）
- 実装：[app/games/game1/battle/page.tsx](../../app/games/game1/battle/page.tsx)の`bgmSrc`state。ボス戦突入時・全滅時・クリア時にそれぞれ`setBgmSrc()`で切り替える

## BGM再生（`components/BgmPlayer.tsx`）

- 画面（ページ）ごとに`<BgmPlayer src="/audio/bgm/xxx.mp3" enabled={bgmEnabled} />`を置く形。`src`が変わった時だけ`new Audio()`で読み込み直し（`loop = true`、音量は`BGM_VOLUME`＝0.5固定の仮値）、`enabled`の変化には`play()`/`pause()`だけで反応する（`pause()`は再生位置を保持するので、OFF→ONで曲の途中から再開できる）
- **BGMは画面に紐づく**。今のところ横断的に鳴らし続ける仕組みは無いため、その画面を離れる（アンマウントされる）と音も止まる。例えばホーム画面からバッグ画面へ切り替えるとホームのBGMは止まる。複数画面をまたいで鳴らし続けたくなったら、`app/games/game1/(main)/layout.tsx`側に引き上げるなど別途検討する
- ブラウザの自動再生ポリシーにより、直前にユーザー操作が無いと`play()`が拒否されることがある。失敗しても例外は投げず、単に鳴らないだけにしている
- 現在BGMが設定されているのは、ゲーム開始画面・ホーム画面・ステージ選択画面・ショップ画面・戦闘画面（上記「画面ごとのBGM割り当て」参照）。いずれも各画面のコンポーネントが`loadGlobalData().bgmEnabled`を自前で読み込んで`enabled`propに渡す（設定はグローバル共有のため、画面をまたいでも同じON/OFF状態になる）

### 自動再生ポリシーへの対応

実際に発生した不具合：ゲーム開始画面（`/games/game1`）のBGMが本番で鳴らなかった。原因は、入口のスプラッシュ画面（`app/page.tsx`）がタップ不要のタイマーで自動的にこの画面へ遷移していたため、BGMがマウント時に自動再生を試みた時点で**このタブで一度もユーザー操作が発生していない**こと。多くのブラウザ（特にiOS Safari）はこの状態での音声再生を拒否する。

**根本対策**：スプラッシュ画面（[start.md](./screens/start.md)）自体を「タップして開始する」を待つ形に変更した。この画面での最初のタップが、アプリ全体での最初のユーザー操作になるため、以降の画面（`/games/game1`を含め、同じタブ内でのクライアントサイド遷移）はすべて「一度はユーザー操作を経た状態」でマウントされ、通常のマウント時自動再生がそのまま成功する（ユーザー確認済み。詳細は[start.md](./screens/start.md#なぜ自動遷移ではなくタップ待ちにしたか)参照）。

**保険としてのリトライ機構**：上記の根本対策に加えて、`BgmPlayer`を`forwardRef`化し、`resume()`（内部の`<audio>`へ再度`play()`を試みるだけの関数）を`useImperativeHandle`で公開している。ゲーム開始画面では実際のクリックハンドラ（`onClick`）の中で同期的に`bgmRef.current?.resume()`を呼んでおり（[app/games/game1/page.tsx](../../app/games/game1/page.tsx)の`handleTap()`参照）、何らかの理由でスプラッシュ側の対策が効かなかった場合のフォールバックとして機能する。

## 設定（BGM・効果音のON/OFF）

実装: [lib/storage.ts](../../lib/storage.ts)の`GlobalSaveData.bgmEnabled`/`seEnabled`（**全ゲーム共有**のデータ。通貨と同じ扱い）、ホーム画面の「設定」アイコンから開く設定シート（[game1-home.md](./screens/game1-home.md#設定)参照）。

- BGM・効果音それぞれに`components/ToggleSwitch.tsx`（iOS風の丸いつまみのON/OFFスイッチ、汎用コンポーネント）を使ったトグルを表示する
- **BGMは実際に音の再生/停止に反映される**（`BgmPlayer`の`enabled`prop経由）
- **効果音は現状、鳴らす効果音自体が実装されていない**ため、UIのトグルと保存だけ用意している（ユーザー確認済み：まずは設定UIだけ先に作っておく）。効果音システムを実装する際は、各効果音の再生前に`loadGlobalData().seEnabled`を見て鳴らすかどうか判定する想定

## BGM一覧・視聴（図鑑画面）

[図鑑画面](./screens/guide.md)の「BGM」タブで、ゲーム内で使っている全曲をタイトル付きで一覧表示し、タップすると再生できる（もう一度タップで停止）。曲名は[lib/audio-tracks.ts](../../lib/audio-tracks.ts)の`BGM_TITLES`（ファイルパス→曲名の対応表。上記「画面ごとのBGM割り当て」表と同じ曲名を使用）から`ALL_BGM_TRACKS`として一覧化している。

- 聴いたことがない曲も含めて**全曲を条件なしで再生できる**（ユーザー確認済みの割り切り。「聞いたことのない曲を聴けてしまってよいか」という論点はあるが、まずはこの形で実装）
- `BgmPlayer`とは別に、図鑑画面が独自に`Audio`インスタンスを1つ持って再生する（**設定のBGM ON/OFFとは独立**：これは「試聴」であり、通常画面のアンビエントBGMとは性質が異なるため）
- タブを「BGM」から離れる・図鑑画面自体を離れると自動的に停止する
