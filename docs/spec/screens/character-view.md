# キャラクター確認画面（`/games/game1/character`）

実装: [app/games/game1/(main)/character/page.tsx](<../../../app/games/game1/(main)/character/page.tsx>)、キャラクターデータ: [lib/character-growth.ts](../../../lib/character-growth.ts)（レベル成長）/ [lib/characters-info.ts](../../../lib/characters-info.ts)（名前・属性など）、装備データ: [lib/game1-data.ts](../../../lib/game1-data.ts)

## 概要

下部ナビゲーションバー（[bottom-nav.md](./bottom-nav.md)）の「仲間」タブから切り替わる、キャラクターのドット絵を1人ずつ確認する画面。スマホを縦向きに持った状態を前提にしたデザイン。上から「名前ヘッダー」「ドット絵待機アニメーション」「装備スロット」「ステータス表示」の4段構成で、**スワイプで動くのは名前ヘッダーとステータス表示の間（ドット絵の表示エリア）だけ**で、上下のUIは固定されている。ドット絵は背景透過のため、写真の額縁のような枠は使わず、他画面と共通の背景（[GameBackground](../visual-design.md#背景流れる文字パターン)）の上に直接表示する。

## 画面構成

1. **最上部：名前ヘッダー**
   - 画面幅いっぱいの黒帯に、現在選択中のキャラクターの正式名称を白文字・中央寄せで表示する（下部ナビゲーションバーの黒帯と対になるデザイン）
   - 右端に小さく「バトルに参加」チェックボックス（詳細は下記「編成（バトルに参加）」参照）。縦方向のスペースを圧迫しないよう、名前と同じ1行に収まる小さいピル型ボタンにしている
2. **ドット絵待機アニメーション（ヘッダーと装備欄の間の可変エリア）**
   - 現在のキャラクターのドット絵を表示する。素材の出所・仕様は、このアプリのリポジトリ外にある画像制作用リポジトリ（`hirogames_images/CHARACTER_SCREEN_ASSETS.md`）で管理されている
   - 各キャラクター1枚のスプライトシート（`public/characters/idle/c{ID}_idle_sheet.png`、486×810px相当のコマを8列×5行=40コマ並べたもの）をCSSの`background-position`で100msごとに切り替え、瞬きや髪・炎・光の粒などがゆっくり動く待機アニメーションとしてループ表示する（4秒で1周、`IDLE_FRAME_COUNT`/`IDLE_FRAME_DURATION_MS`）。フレーム送りは`setInterval`ベース（画面全体で1つのタイマーを共有し、表示中の前後3キャラクター分を同期させている）
   - 顔・胸・お腹・腰・足元の位置はコマ間で固定という素材側の仕様のため、切り替わっても違和感のないループになる。拡大時も`image-rendering: pixelated`でドットの角を保っている
   - 表示エリアいっぱいに等倍表示すると上下のヘッダー・装備欄と際どく重なることがあるため、あえて一回り小さく（高さ96%・最大幅92%）表示して余白を持たせている
3. **装備スロット**
   - 4枠を横並びで表示。**一番左が武器スロット、残り3枠がアーティファクトスロット**（[items.md](../items.md)参照）
   - 空欄は「＋」表示の点線枠。装備しているスロットはアイテムアイコンを表示し、合成で強化済み（`plus`が1以上）の個体は右下に「+N」バッジを重ねる
4. **ステータス表示＋「訓練」「合成」ボタン（最下部、下部ナビゲーションバーの直前）**
   - 上段に「レベル」を単独表示し、その下を2段組み（`grid-cols-2`）で HP／会心率、攻撃力／会心ダメージ、防御力／属性耐性 の3行を並べる
     - レベルは`getCharacterLevel()`（投入済み経験値ポイントの累計から逆算、[lib/game1-data.ts](../../../lib/game1-data.ts)）、HP・攻撃力・防御力はそのレベルでの実際の値（[lib/character-growth.ts](../../../lib/character-growth.ts)の`getCharacterStatsAtLevel()`）に、装備中のアイテムによる加算（[lib/item-effects.ts](../../../lib/item-effects.ts)）を乗せた値。会心率（基礎10%）・会心ダメージ（基礎150%、いずれも[lib/combat.ts](../../../lib/combat.ts)と同じ値）・属性耐性（基礎0%）も同様に装備の加算分を反映する。装備ごとの効果対応表・上昇量（武器は固定値、アーティファクトは％／pt）は[items.md](../items.md#装備によるステータス加算)参照。戦闘（[battle-test.md](./battle-test.md)）でもこれと同じ計算関数を使う
   - ステータスカードの下に「訓練」「合成」「スキル」の3ボタンを、**画面横幅を3等分**して横並びに表示する（縦に積まず、ラベルのみ・残量などの補足テキストは表示しない。ドット絵表示エリアをできるだけ広く取るための配置）
     - 「訓練」：タップするとボトムシートが開く。渡すポイント数を入力して「決定」すると、そのキャラクターの累計投入経験値（`characterInvestedExp`）に加算され、必要に応じてレベルが上がる（[lib/game1-data.ts](../../../lib/game1-data.ts)の`investExpInCharacter()`）。渡した量が保有ポイント（`Game1SaveData.expPoints`）を超える場合や0以下の場合はエラーメッセージを表示するだけで何も起きない（成功時は[デイリーミッション](./game1-home.md#デイリーミッション)「育成」の進捗としても1回分カウントされる。合成の成功時も同様）
     - 「合成」：武器・アーティファクトの強化を行う（詳細は下記「合成の操作」参照）
     - 「スキル」：そのキャラクターの4スキル（[skills.md](../skills.md)参照）を一覧できるボトムシートが開く（詳細は下記「スキルの操作」参照）
   - 下部ナビゲーションバーと重ならないよう、下側に余白を空けている

## 表示対象は「仲間になっているキャラクター」だけ

[冒険システム設計](../adventure-system.md#キャラクターの仲間解放)の通り、キャラクターはステージクリアで順次仲間になる（`maxClearedStage`で判定）。この画面のスワイプ対象は**まだ仲間になっていないキャラクターを含まない**（[characters-info.ts](../../../lib/characters-info.ts)の`CHARACTER_BASE_INFO`全4体のうち、解放済みのものだけに絞り込む）。序盤はアカネ1人だけの状態になる。[テストモード](../test-mode.md)中は全員解放済み扱いになる。

## 編成（バトルに参加）

- 名前ヘッダー右端のチェックボックス「参加」で、そのキャラクターを編成に入れるかどうかを切り替える。最大3人まで（`MAX_PARTY_SIZE`）
- 4人揃うまでは、新しく仲間になったキャラクターは自動でチェックON（`syncActivePartyWithUnlocks()`、画面を開くたびに同期）。あえて外すことは可能
- すでに3人編成済みの状態で4人目を追加しようとすると、ボタンのラベルが一瞬「上限3人」に変わって弾かれる（他の誰かを先に外す必要がある）
- 保存先：[lib/game1-data.ts](../../../lib/game1-data.ts)の`Game1SaveData.activePartyIds`
- 専用の編成画面は無く、この画面のチェックボックスだけで完結する簡易な仕様（[adventure-system.md](../adventure-system.md)参照）

## スワイプ操作

- **仲間になっているキャラクターが2人以上いる場合のみ**、ドット絵の表示エリアでドラッグ（`onPointerDown` / `onPointerMove` / `onPointerUp`、Pointer Events）すると、前・現在・次の3人分の待機アニメーションを横に並べたトラックが指の動きに追従してリアルタイムにスライドする。ヘッダー・装備欄・ステータス表示は動かない
  - **1人しか仲間になっていない間はスワイプ操作自体を無効化する**（`unlockedCharacters.length > 1`のときだけドラッグを受け付ける）。切り替え先がいない状態でスワイプしても何も起きないと分かりにくいため
  - **左**にスワイプ → 次のキャラクターへ（解放済みキャラクターの中でループ）
  - **右**にスワイプ → 前のキャラクターへ（逆順）
  - ドラッグの横移動量が60px（`SWIPE_THRESHOLD`）を超えた状態で指を離すと、そのまま外まで滑って次/前のキャラクターに切り替わる（250ms、`SNAP_DURATION`）。届かなければ元の位置にスナップバックして切り替わらない
  - 切り替え後、トラックの位置を（アニメーション無しで）中央に瞬時にリセットすることで、無限ループしているように見せている
- **キャラクターが完全に切り替わったタイミング（スライド完了後）で、名前ヘッダーとステータス表示も新しいキャラクターの値に切り替わる**。ドラッグ中は元のキャラクターの値のまま変化しない
- この画面はスクロール不要なため、`touch-action: none`（Tailwindの`touch-none`）を画面全体とドット絵表示エリアの両方に指定し、上下方向のブラウザ標準スワイプ（スクロール）を無効化している。左右のスワイプ判定はブラウザの標準機能ではなく自前のPointer Events処理で行っているため、これで干渉せず動作する

## 装備の操作

- 空欄・装備済みどちらのスロットをタップしても、その枠に装備できるアイテムの選択シート（画面下からせり上がるボトムシート、8列グリッド）が開く。所持数が多いとアイテムを探すのにスクロールが大変になるため、シートの高さは画面の92%（`max-h-[92vh]`）まで広く取っている（「シートらしさ」より一覧性を優先、ユーザー確認済み）
  - 武器スロット：現在のキャラクターの`weaponType`（[characters-info.ts](../../../lib/characters-info.ts)）と一致する、**所持している**個体だけを候補にする
  - アーティファクトスロット：`type`が「アーティファクト」の所持個体を候補にする。**同じキャラクターの他のアーティファクトスロットに装備済みのものは候補から除外**する（同じ個体を2箇所に付けられないようにするため）
  - **所持数分しか装備できない**（前提事項）。武器・アーティファクトを問わず、いずれかのキャラクターの装備欄で今使われている個体は、他のスロットの候補一覧から除外される（[lib/game1-data.ts](../../../lib/game1-data.ts)の`isInstanceEquippedElsewhere()`、詳細は[items.md](../items.md#装備によるステータス加算)参照）。今このスロットに装備中の個体自身は、選び直せるよう候補から除外しない
  - 各候補には合成の「+N」バッジ（強化済みの場合）を表示する
  - 候補をタップするとその場で装備され、シートが閉じる
  - スロットに何か装備されている状態でシートを開くと、右上に「外す」ボタンが出る（タップでそのスロットを空にする）
  - 候補が0件のときは「装備できる武器/アーティファクトを持っていません」と表示する
- 装備は**キャラクターごと**に記録する（`Game1SaveData.equipment`、キャラID→装備の対応。値は個体ID）。スワイプで別のキャラクターに切り替えると、そのキャラクター自身の装備状況に表示が変わる

## 合成の操作

実装: [lib/item-synthesis.ts](../../../lib/item-synthesis.ts)。ルールの詳細は[items.md](../items.md#アイテムの合成強化)参照。

- 「合成」ボタンをタップすると、まず**残す方（対象）を選ぶ**ボトムシートが開く（こちらも装備選択シートと同じく`max-h-[92vh]`）。候補は「未装備の所持アイテム」と「**今表示中のキャラクター自身**が装備中のアイテム」（他のキャラクターの装備は候補に出ない）。8列グリッドで、強化済みの個体には「+N」バッジを表示する
- 対象を選ぶと、**同じ合成グループ（同じ武器種、または同じアーティファクトslot）の個体だけ**が素材候補として表示される。複数選択可（タップで選択トグル、選択中は右上に✓バッジ）
- 素材を1つ以上選ぶと、結果のプレビュー（「アイテム名　+現在値 → +変化後の値」）をリアルタイムに表示する。変化が無い（切り捨てで+0のまま）組み合わせもそのまま見える
- 「合成する」を押すと確定。合成後に残らない個体（生存者以外）は所持アイテムから削除され、どこかに装備されていた場合は自動的に装備が外れる
- 「戻る」で対象の選び直しから、シート外タップ（暗い部分）または「閉じる」で操作自体をキャンセルできる

## スキルの操作

実装: [lib/skill-progression.ts](../../../lib/skill-progression.ts)。ルールの詳細は[skills.md](../skills.md#スキルの解放強化スキルポイント)参照。

- 「スキル」ボタンをタップすると、現在表示中のキャラクターの4スキル（通常攻撃を除く枠2〜5）を縦に並べたボトムシートが開く。各行にアイコン・名称・状態（未解放／解放済みなら「+N」）・説明文と、右端に「解放」または「強化」ボタン（いずれも消費pt数を併記）を表示する
  - **未解放のスキルはアイコン・名称・説明文を見せない**（🔒アイコンと「？？？」「未解放のスキル」とだけ表示する）。解放するまでどんなスキルかネタバレしないようにするための仕様（ユーザー確認済み）
- ボタンをタップすると、スキルポイントを10pt消費して該当スキルへ投入する（`investSkillPoints()`）。未解放なら解放（+0になる）、解放済みならさらに+1される
- 所持スキルポイントが10pt未満の場合はボタンが押せない状態（`disabled`）になる
- 「閉じる」またはシート外タップでシートを閉じる

## 今後

- ステータスの値・装備の効果量ともに仮の数値。正式な数値・バランス調整は別途行う
- 「訓練」ボタンの名称は仮。レベルアップに必要な経験値ポイントのカーブも仮の数値（[adventure-system.md](../adventure-system.md#経験値とレベル成長)参照）
- スキルの育成効果（攻撃スキルの`baseValue`上昇）は反映済みだが、支援・回復スキルの効果量は強化段階の影響を受けない（今後の検討事項、詳細は[skills.md](../skills.md)参照）
- キャラクターの名前・プロフィールなど、ステータス以外の表示項目は未定
- 待機アニメーションは4人分とも同じ8列×5行・40コマ・100ms間隔の仕様で揃っているが、素材側（`hirogames_images`リポジトリ）が更新された場合は`public/characters/idle/`配下の該当ファイルを差し替えるだけで反映される
