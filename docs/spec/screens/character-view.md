# キャラクター確認画面（`/games/game1/character`）

実装: [app/games/game1/(main)/character/page.tsx](<../../../app/games/game1/(main)/character/page.tsx>)、キャラクターデータ: [lib/characters.ts](../../../lib/characters.ts) / [lib/characters-info.ts](../../../lib/characters-info.ts)、装備データ: [lib/game1-data.ts](../../../lib/game1-data.ts)

## 概要

下部ナビゲーションバー（[bottom-nav.md](./bottom-nav.md)）の「仲間」タブから切り替わる、キャラクターのドット絵を1人ずつ確認する画面。スマホを縦向きに持った状態を前提にしたデザイン。上から「名前ヘッダー」「ドット絵待機アニメーション」「装備スロット」「ステータス表示」の4段構成で、**スワイプで動くのは名前ヘッダーとステータス表示の間（ドット絵の表示エリア）だけ**で、上下のUIは固定されている。ドット絵は背景透過のため、写真の額縁のような枠は使わず、他画面と共通の背景（[GameBackground](../visual-design.md#背景流れる文字パターン)）の上に直接表示する。

## 画面構成

1. **最上部：名前ヘッダー**
   - 画面幅いっぱいの黒帯に、現在選択中のキャラクターの正式名称を白文字・中央寄せで表示する（下部ナビゲーションバーの黒帯と対になるデザイン）
   - 右端に小さく「バトルに参加」チェックボックス（詳細は下記「編成（バトルに参加）」参照）。縦方向のスペースを圧迫しないよう、名前と同じ1行に収まる小さいピル型ボタンにしている
2. **ドット絵待機アニメーション（ヘッダーと装備欄の間の可変エリア）**
   - 現在のキャラクターのドット絵を表示する。素材の出所・仕様は、このアプリのリポジトリ外にある画像制作用リポジトリ（`hirogames_images/CHARACTER_SCREEN_ASSETS.md`）で管理されている
   - 各キャラクター1枚のスプライトシート（`public/characters/idle/c{ID}_idle_sheet.png`、486×810px相当のコマを8列×5行=40コマ並べたもの）をCSSの`background-position`で100msごとに切り替え、瞬きや髪・炎・光の粒などがゆっくり動く待機アニメーションとしてループ表示する（4秒で1周、`IDLE_FRAME_COUNT`/`IDLE_FRAME_DURATION_MS`）。フレーム送りは`setInterval`ベース（画面全体で1つのタイマーを共有し、表示中の前後3キャラクター分を同期させている）
   - 顔・胸・お腹・腰・足元の位置はコマ間で固定という素材側の仕様のため、切り替わっても違和感のないループになる。拡大時も`image-rendering: pixelated`でドットの角を保っている
   - 表示エリアいっぱいに等倍表示すると上下のヘッダー・装備欄と際どく重なることがあるため、あえて一回り小さく（高さ96%・最大幅92%）表示して余白を持たせている
3. **装備スロット**
   - 4枠を横並びで表示。**一番左が武器スロット、残り3枠がアーティファクトスロット**（[items.md](../items.md)参照）
   - 空欄は「＋」表示の点線枠。装備しているスロットはアイテムアイコンを表示する
4. **ステータス表示（最下部、下部ナビゲーションバーの直前）**
   - 上段に「レベル」（`characterLevels`、未設定は1として扱う）を単独表示し、その下を2段組み（`grid-cols-2`）で HP／会心率、攻撃力／会心ダメージ、防御力／属性耐性 の3行を並べる
     - HP・攻撃力・防御力は[lib/characters.ts](../../../lib/characters.ts)の`CHARACTERS`から取得（現時点では全て仮の値）
     - 会心率（10%固定）・会心ダメージ（150%固定）・属性耐性（0%固定）は現状すべて装備なしの基礎値のプレースホルダー（アーティファクトなどによる加算は未実装）
   - 下部ナビゲーションバーと重ならないよう、下側に余白を空けている

## 表示対象は「仲間になっているキャラクター」だけ

[冒険システム設計](../adventure-system.md#キャラクターの仲間解放)の通り、キャラクターはステージクリアで順次仲間になる（`maxClearedStage`で判定）。この画面のスワイプ対象は**まだ仲間になっていないキャラクターを含まない**（`lib/characters.ts`の`CHARACTERS`全4体のうち、解放済みのものだけに絞り込む）。序盤はアカネ1人だけの状態になる。

## 編成（バトルに参加）

- 名前ヘッダー右端のチェックボックス「参加」で、そのキャラクターを編成に入れるかどうかを切り替える。最大3人まで（`MAX_PARTY_SIZE`）
- 4人揃うまでは、新しく仲間になったキャラクターは自動でチェックON（`syncActivePartyWithUnlocks()`、画面を開くたびに同期）。あえて外すことは可能
- すでに3人編成済みの状態で4人目を追加しようとすると、ボタンのラベルが一瞬「上限3人」に変わって弾かれる（他の誰かを先に外す必要がある）
- 保存先：[lib/game1-data.ts](../../../lib/game1-data.ts)の`Game1SaveData.activePartyIds`
- 専用の編成画面は無く、この画面のチェックボックスだけで完結する簡易な仕様（[adventure-system.md](../adventure-system.md)参照）

## スワイプ操作

- **仲間になっているキャラクターが2人以上いる場合のみ**、ドット絵の表示エリアでドラッグ（`onPointerDown` / `onPointerMove` / `onPointerUp`、Pointer Events）すると、前・現在・次の3人分の待機アニメーションを横に並べたトラックが指の動きに追従してリアルタイムにスライドする。ヘッダー・装備欄・ステータス表示は動かない
  - **1人しか仲間になっていない間はスワイプ操作自体を無効化する**（`unlockedCharacters.length > 1`のときだけドラッグを受け付ける）。切り替え先がいない状態でスワイプしても何も起きないと分かりにくいため
  - **左**にスワイプ → 次のキャラクターへ（解放済みキャラクターの中でループ）
  - **右**にスワイプ → 前のキャラクターへ（逆順）
  - ドラッグの横移動量が60px（`SWIPE_THRESHOLD`）を超えた状態で指を離すと、そのまま外まで滑って次/前のキャラクターに切り替わる（250ms、`SNAP_DURATION`）。届かなければ元の位置にスナップバックして切り替わらない
  - 切り替え後、トラックの位置を（アニメーション無しで）中央に瞬時にリセットすることで、無限ループしているように見せている
- **キャラクターが完全に切り替わったタイミング（スライド完了後）で、名前ヘッダーとステータス表示も新しいキャラクターの値に切り替わる**。ドラッグ中は元のキャラクターの値のまま変化しない
- この画面はスクロール不要なため、`touch-action: none`（Tailwindの`touch-none`）を画面全体とドット絵表示エリアの両方に指定し、上下方向のブラウザ標準スワイプ（スクロール）を無効化している。左右のスワイプ判定はブラウザの標準機能ではなく自前のPointer Events処理で行っているため、これで干渉せず動作する

## 装備の操作

- 空欄・装備済みどちらのスロットをタップしても、その枠に装備できるアイテムの選択シート（画面下からせり上がるボトムシート、[bag.md](./bag.md)の詳細シートと同じ形式）が開く
  - 武器スロット：現在のキャラクターの`weaponType`（[characters-info.ts](../../../lib/characters-info.ts)）と一致する、**所持している**アイテムだけを候補にする
  - アーティファクトスロット：`type`が「アーティファクト」の所持アイテムを候補にする。**同じキャラクターの他のアーティファクトスロットに装備済みのものは候補から除外**する（同じ物を2箇所に付けられないようにするため）
  - 候補をタップするとその場で装備され、シートが閉じる
  - スロットに何か装備されている状態でシートを開くと、右上に「外す」ボタンが出る（タップでそのスロットを空にする）
  - 候補が0件のときは「装備できる武器/アーティファクトを持っていません」と表示する
- 装備は**キャラクターごと**に記録する（`Game1SaveData.equipment`、キャラID→装備の対応）。スワイプで別のキャラクターに切り替えると、そのキャラクター自身の装備状況に表示が変わる
- 同じアイテムを複数のキャラクターに同時に装備させることについては、現状チェックしていない（今後の検討事項）
