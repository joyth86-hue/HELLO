# アプリ起動画面（`/`）

実装: [app/page.tsx](../../../app/page.tsx)

## 概要

アプリを開いたときに最初に表示される、演出だけの画面。タイトルロゴがフェードインした後「タップして開始する」を表示し、タップするとGame 1の開始画面（[game1.md](./game1.md)、`/games/game1`）に遷移する。

このアプリはもともと複数ゲームをまとめるハブ（ユーザー名登録＋ゲーム選択メニュー）を持つ構成だったが、「ゲームごとに入り口を分けたほうがよい」という方針に変更し、そのハブ（旧スタート画面・旧ゲームメニュー画面 `/menu`）は廃止した。今後別のゲームを追加する場合も、同様に専用の入り口画面を用意する想定。

## 表示・演出

- 黒背景
- 画面を開いてから約1秒後、タイトルロゴ画像（`public/logos/l01.png`、"hg"マーク＋「hiro games」の白ロゴ）がフェードイン（`transition-opacity duration-[800ms]`）
- フェードイン開始から約0.8秒後（画面表示から約1.8秒後）、画面下部に「タップして開始する」が表示される。タップすると`/games/game1`へ遷移する

### なぜ自動遷移ではなくタップ待ちにしたか

以前はタップ不要でタイマーのみで自動遷移していたが、その場合「このタブで一度もユーザー操作が発生しないまま」次の開始画面（[game1.md](./game1.md)）へ進んでしまい、その画面のBGM（はじまり）がブラウザの自動再生ポリシーで再生を拒否され続ける不具合につながっていた（[audio.md](../audio.md#自動再生ポリシーへの対応resume)参照）。この画面での最初のタップを、アプリ全体での最初のユーザー操作にすることで、以降の画面（`/games/game1`を含む、同じタブ内でのクライアントサイド遷移）でBGMが表示直後から自動再生できるようにしている（ユーザー確認済み）。
