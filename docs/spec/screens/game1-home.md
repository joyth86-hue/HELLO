# Game 1 ホーム画面（`/games/game1/home`）

実装: [app/games/game1/(main)/home/page.tsx](<../../../app/games/game1/(main)/home/page.tsx>)

## 概要

[Game 1開始画面](./game1.md)でタップした後に表示される、Game1のメイン画面。他画面（[character-view.md](./character-view.md)、[bag.md](./bag.md)）が使う[流れる文字パターンの共通背景](../visual-design.md#背景流れる文字パターン)（`GameBackground`）とは別に、この画面専用の背景イラストを敷いている。

## 背景イラスト

仲間の拠点（ギルドホール風の部屋）のイラストで、**解放済みの仲間の人数に応じて背景に描かれるキャラクターの人数も増える**（`home_01`=1人〜`home_04`=4人）。画像は[public/backgrounds/home/](../../../public/backgrounds/home/)に4種類（`home_01_akane.png` / `home_02_akane_koyuki.png` / `home_03_akane_koyuki_kaede.png` / `home_04_akane_koyuki_kaede_sayumi.png`）が揃っており、いずれも[仲間解放順](../adventure-system.md#キャラクターの仲間解放)（アカネ→コユキ→カエデ→サユミ）に対応した構図になっている。

`getUnlockedCharacterIds()`（[lib/game1-data.ts](../../../lib/game1-data.ts)）で解放済みキャラクター数を求め、`getHomeBackground()`でその人数に対応する画像を選ぶ（`HOME_BACKGROUNDS`配列）。**編成している人数（`activePartyIds`、[MAX_PARTY_SIZE](../adventure-system.md#編成バトルに参加)=3）ではなく解放済みの人数（最大4）で選ぶ**点に注意（キャラクターは4人いるが編成枠は3人までのため、編成人数を使うと4人目が仲間になっても背景が変わらない）。

## 表示要素

- 右上：所持金（共通通貨、全ゲーム共有）と経験値（`expPoints`、`game1`のセーブデータ）を2行で表示する小さなパネル（`所持金：XXXモラ` / `経験値：YYYpt`）。背景イラストの上でも読めるよう、不透明度の高いダークガラス風のパネルにしている
- 画面上半分の右端（カエデの横の空きスペース）：導線ボタン4つを縦並びで配置。上から「プレゼント」「デイリーミッション」「図鑑」「設定」（[共通UIボタン素材](../ui-buttons.md)の`ui_present` / `ui_daily_missions` / `ui_guide` / `ui_settings`を使用、56px角）。「プレゼント」は[テストモード](../test-mode.md)切り替え用の「コードを入力」シート、「デイリーミッション」は下記のミッションシート、「設定」は下記の設定シートを開く。「図鑑」は[図鑑画面](./guide.md)（`/games/game1/guide`）へ遷移する
- ホーム画面には[BGM](../audio.md)（`odayakana-toki.mp3`＝「穏やかなとき」）が流れる。この画面を離れると（アンマウントされると）止まる
- 見出しや共通通貨カードなどの装飾要素は表示せず、上記パネル・導線ボタンと下部の「冒険に行く」ボタンのみのシンプルな構成にしている（画面を開くたびにプレイ回数`playCount`は+1しセーブデータに保存しているが、画面上には表示しない）
- 「冒険に行く」ボタン：画面下部（`mt-auto`で下寄せ）に配置。[ステージ選択画面](./stages.md)（`/games/game1/stages`）へ遷移する
- 画面下部には[下部ナビゲーションバー](./bottom-nav.md)が常時表示される（この画面固有のボタンではなく、マップ/ショップ/仲間/バッグと共通のもの。このホーム画面自体が「冒険」タブに対応する）

## デイリーミッション

実装: [lib/daily-missions.ts](../../../lib/daily-missions.ts)（進捗・受取状態の管理）、`Game1SaveData.dailyMissions`（保存先）。ユーザー確認済みのルール：

- ミッションは5つ固定。**達成と受取は別**で、達成しても「受け取る」ボタンをタップするまで報酬は入らない
  1. 「ゲームにログインする」：ホーム画面を開いた時点で自動達成→経験値+20pt
  2. 「バトルに3回勝利する」：[戦闘画面](./battle-test.md)の1バトルごとにカウント→経験値+30pt
  3. 「ステージを1つクリアする」：ボス撃破→**ガチャチケット×1**
  4. 「訓練か合成を1回行う」：[キャラクター画面](./character-view.md)の訓練または合成→スキルポイント+5pt
  5. 「全てのミッションを達成する」：上記4つを全て受け取った状態が条件→**ガチャチケット×1**
- ガチャチケットが出るのはステージクリアとコンプリートの2つだけ＝**1日最大2枚**（[shop.md](./shop.md)のガチャで使う）。宝箱は必ず1つ手に入る強力な報酬のため、意図的に少なめに抑えている（詳細な検討経緯は[shop.md](./shop.md)参照）
- 進捗はローカル日付（`YYYY-MM-DD`）を基準に管理し、日付が変わると（`getEffectiveDailyMissions()`）その日の進捗・受取状態は自動的に0・未受取へ戻る。書き戻しはホーム画面を開いた時点（ログインボーナスの達成タイミングと合わせて）で行われる
- シートは「デイリーミッション」アイコンから開く、`max-h-[80vh]`のボトムシート。**各ミッションは1行のみ**（達成条件の説明文のみ、`lib/daily-missions.ts`の`MISSION_LIST`の`description`）で、右端に「未達成」（灰色・押せない）／「受け取る」／「受取済み」のボタンを表示する。タイトル・報酬・進捗（`n/m`）は行には出さない（3行あって冗長との指摘を受けて簡略化、ユーザー確認済み）
- 報酬の内容は行には出さず、**「受け取る」をタップした時にポップアップで見せる**。このポップアップは[戦闘結果フレーム](./battle-test.md#結果フレームクリア全滅)と同じ見た目（不透明な濃い紫`#241f47`のカード、中央表示、タップして閉じる）で揃えている（ユーザー確認済み：「戦闘後のメッセージの様な感じ」という指定）

## 設定

実装: `Game1HomePage`内の設定シート、保存先は[GlobalSaveData](../save-data.md#共有データglobalsavedata)の`bgmEnabled`/`seEnabled`（全ゲーム共有）。詳細は[audio.md](../audio.md)参照。

- 「設定」アイコンをタップすると、BGM・効果音それぞれのON/OFFスイッチ（`components/ToggleSwitch.tsx`、iOS風の丸いつまみ）を並べたボトムシートが開く
- BGMのトグルは実際に再生/一時停止に反映される。効果音のトグルは、効果音自体がまだ実装されていないため保存だけされる（UIの下に「未実装のため、今はON/OFFの設定のみ反映されます」と注記）

## 実装上の注意（ハマりどころ）

- 右端の導線ボタン（`z-10`）と、下部の「冒険に行く」を囲む全画面div（同じく`z-10`、`h-full`で画面全体を覆っている）は、以前どちらも同じz-10のままだった。CSSは同ランクのz-indexだと後からDOMに現れる要素が上に乗るため、後に書かれている全画面div側がタップ判定だけ導線ボタンより上に乗ってしまい、**見た目には普通に表示されるのに「プレゼント」がタップしても反応しない**という気づきにくい不具合が実際に発生していた。導線ボタン側を`z-20`に上げて解消している。

## 今後

- 「冒険」タブ（＝このホーム画面）の中身は、拠点機能の見せ方が決まり次第この仕様書と実装を更新する。
- 背景イラスト（`home_04`）だと、下部ナビゲーションバー導入前は「キャラクター」「バッグの中身」ボタンの端がキャラクターの頭に軽く重なっていた。ナビゲーションバーへの移行でボタン自体が画面下部に集約されたため、その重なりは解消している。
- 「ゲームを終了」（`/`に戻る）ボタンは、下部ナビゲーションバーへの移行にあたって一旦なくなった。必要であれば別の場所（設定画面など）に置き直すことを検討する。
