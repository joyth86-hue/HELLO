# ショップ（武器ガチャ）画面（`/games/game1/shop`）

実装: [app/games/game1/(main)/shop/page.tsx](<../../../app/games/game1/(main)/shop/page.tsx>)

## 概要

下部ナビゲーションバー（[bottom-nav.md](./bottom-nav.md)）の「ショップ」タブ＝武器ガチャ画面。**ガチャチケット**（[ホーム画面のデイリーミッション](./game1-home.md#デイリーミッション)で入手、`Game1SaveData.gachaTickets`）を1枚消費して宝箱を1回開け、必ず武器かアーティファクトが1つ手に入る。

## レア度の決まり方

実装: [lib/item-drop.ts](../../../lib/item-drop.ts)の`rollGachaItem()`。

- レア度は「**現在クリアしている中で最大のステージ**（`maxClearedStage`）」の抽選テーブル（`RARITY_BLOCKS`）で決まる。これは戦闘ドロップ（[items.md](../items.md#アイテムドロップ)）と全く同じテーブルで、序盤ほど低レア中心・終盤ほど高レアが混ざる
- 戦闘ドロップとの違いは「そもそも落ちるか」の判定（通常3%／ボス5%）が無いこと。チケットを使えば**必ず**1つ手に入る（`rollGachaItem()`は`rollDropForBattle()`から確率判定だけを抜いたもの）
- レア度が決まった後、そのレア度の全アイテム（武器種・アーティファクト問わず）から均等ランダムで1つ選ぶ（戦闘ドロップと同じロジックを共有）

## 演出素材

元データ：`C:\Users\田中宏樹\Documents\Codex\hirogames_images\assets\gacha\chest_reveal_v1\`（このアプリのリポジトリ外にある画像制作用フォルダ、`README.md`に仕様あり）。[characters.md](../characters.md)・[items.md](../items.md)と同様、元フォルダの中身は変更せず、使う分だけ`public/`へコピーして使う。

- コピー元：`frames/<rarity>/frame_00.png`〜`frame_08.png`（レア度ごとのVFXを合成済み、512×512px透過PNG、9フレーム）
- コピー先：[public/gacha/chest/\<rarity\>/frame_00.png](../../../public/gacha/chest/)〜`frame_08.png`（`rarity`は`C`/`B`/`A`/`S`/`SS`）
- `frames/base/`（VFX無しの共通宝箱9フレーム）はコピーしていない。各`frames/<rarity>/`側に既にベースの宝箱＋そのレア度のVFXが合成済みのため、そちらだけで単独再生できる

各フレームの表示時間（ms）は元データの生成スクリプト（`build_animations.py`）にある`DURATIONS = [180, 80, 80, 90, 100, 120, 140, 180, 420]`をそのまま`FRAME_DURATIONS_MS`として踏襲している（最後のフレームだけ長め＝開封後の余韻）。

## 画面の流れ

1. **待機状態**：中央に閉じた宝箱（`frame_00`、レア度VFX無しなので見た目はどのレア度でも共通）と、上部に所持チケット枚数（「ガチャチケット N枚」）を表示。チケットが1枚以上あれば「宝箱をタップして開ける」、0枚なら宝箱を薄く表示し「ガチャチケットがありません（デイリーミッションで入手できます）」と案内する
2. **タップ**（チケット1枚以上のときのみ）：まず抽選・チケット消費・所持アイテムへの追加を**先に確定させて保存**する（`rollGachaItem()` → `addItemsToInventory()` → `saveGame1Data()`）。演出はその後に再生するので、演出の途中で画面を離れても結果は残る
3. 確定したレア度の`frame_00`〜`frame_08`を`FRAME_DURATIONS_MS`の間隔で順番に表示する（`setTimeout`ベースのPromiseチェーン、戦闘画面の演出と同じ方式）
4. **結果表示**：宝箱の代わりに獲得したアイテムの実画像を表示し、その下に「\<アイテム名\>（\<レア度\>）を獲得！」をレア度ごとの色（下表）で表示する。所持数上限（[items.md](../items.md#アイテムの個体管理合成のための前提)、100個体）で受け取れなかった場合はその旨を注記する
5. 「もう一度引く」（チケットが残っていれば）または「閉じる」（0枚になったら）ボタンで待機状態に戻る。連打で演出が壊れないよう、演出中はボタンを`disabled`にしている

**画像の先読み**：`<img src>`をフレームごとに切り替えるだけだと、初回は取得・デコードが再生に間に合わず「最初のコマから急に開封後の絵へ飛ぶ」ように見えるコマ落ちが実際に発生した。対策として、画面表示時（`useEffect`）に5レア度×9枚すべてを`Image().decode()`で先読みしておき、宝箱タップ時にも念のためそのレア度分の先読み完了を待ってから再生を始めるようにしている（`preloadImage()`/`preloadRarity()`）。

## チケット枚数の設計メモ

宝箱は戦闘ドロップ（3〜5%）と違って必ず1つ手に入るため、デイリーミッションでの配布枚数はバランス上重要な調整レバーになる。1ステージクリア（9通常戦+1ボス戦）あたりの戦闘ドロップ期待値は約0.32個で、**チケット1枚 ≒ 約3.1ステージクリア分のドロップ期待値**に相当する。1日の配布上限を2枚（ステージクリア報酬＋コンプリートボーナス、[game1-home.md](./game1-home.md#デイリーミッション)参照）に抑えているのはこの計算に基づく（ユーザー確認済み）。
