# 戦闘画面（`/games/game1/battle`）

実装: [app/games/game1/battle/page.tsx](../../../app/games/game1/battle/page.tsx)

## 概要

[戦闘画面の配置設計](./battle.md)（仲間・敵を3体ずつ左右対称に配置するレイアウト）を使った、**ステージ内10バトル連戦（`S-1`〜`S-10`）の本実装**。詳細ルールは[adventure-system.md](../adventure-system.md)参照。下部ナビゲーションバー（[bottom-nav.md](./bottom-nav.md)）の管理下には無い、独立した画面（マップ/ショップ/冒険/仲間/バッグの5タブ画面とは別のルート）。

数値（ステージ係数・敵の基礎ステータス・レベル成長・必要経験値カーブなど）はすべて仮で、後から係数を書き換えるだけで調整できる形にしている（[adventure-system.md](../adventure-system.md)参照）。

## 入り口

[ステージ選択画面](./stages.md)（`/games/game1/stages`）の各ステージから、`/games/game1/battle?stage=<ステージ番号>`という形で遷移してくる。

## パーティ・敵の生成

- **仲間**：`Game1SaveData.activePartyIds`（実際の編成、1〜3人）をそのまま使う。各キャラのHP/攻撃力/防御力は、そのキャラの現在レベル（[character-growth.ts](../../../lib/character-growth.ts)の`getCharacterStatsAtLevel`）に、装備中のアイテムによる加算（[item-effects.ts](../../../lib/item-effects.ts)の`calculateEquipmentBonus`/`applyEquipmentBonusToStats`）を乗せて算出する。会心率・会心ダメージの装備加算も同様に、通常攻撃のダメージ計算に反映される
- **敵**：ステージ番号から出現パターン（4色ローテーション、[enemy-scaling.ts](../../../lib/enemy-scaling.ts)の`pickRandomEnemyFromPattern`）を決め、そこからランダムに選ぶ。`S-1`〜`S-9`は3体、`S-10`（ボス）は1体（中央スロットに配置）。ステータス（HP/攻撃力/防御力）は「基礎値 × ステージ係数（`stageCoefficient`、2次関数カーブ）× 個体差（±10%、バトルごとに再抽選）」、経験値だけは別の緩やかな係数（`expCoefficient`、線形）を使う。ボスだけ追加でステータス×1.6・経験値×3
- **背景**：ステージ番号から`getFieldImagePathForStage()`で1ステージ＝1背景を固定で割り当てる（`f01`〜`f10`を10刻みで繰り返し）

## 10バトル連戦の進行

- `S-1`開始時に仲間は全員全回復した状態で始まり、そのステージを抜けるまでHPは持ち越される（敵は毎バトル新規生成）
- 1バトルごとに、生存している敵が全滅したら次のバトル（`S-s+1`）へ自動で進む（ステージ選択画面には戻らない）
- 仲間が全滅した場合：そのステージは未クリアのまま（`maxClearedStage`は更新しない）だが、**それまでに完全にクリアしたバトル分の経験値・ドロップ、および全滅した瞬間のバトルで倒せた敵の分の経験値**は`expPoints`・`inventory`に加算してから「敗北…」を表示してホーム画面へ戻る（次に挑む時は必ず`S-1`から）
- `S-10`（ボス）を撃破した場合：そのステージ内で倒した敵の経験値合計を`expPoints`に加算し、`maxClearedStage`を更新して保存。**スキルポイント**も固定量（`SKILL_POINTS_PER_STAGE_CLEAR`、[skills.md](../skills.md#スキルの解放強化スキルポイント)参照）を`skillPoints`に加算する（全滅時の部分回収には含まれない、クリア時のみ）。ドロップしたアイテム（[lib/item-drop.ts](../../../lib/item-drop.ts)、通常バトル3%／ボス戦5%でバトルごとに独立抽選）も`inventory`に加算する。「ステージクリア！」を表示してからホーム画面へ戻る
- クリア・敗北いずれの場合も、獲得経験値・獲得スキルポイント・獲得アイテム一覧（アイコン＋名前＋個数）が0以上あれば結果画面に表示する（アイテムがある場合は表示時間を少し延長）。両者で報酬の反映処理は共通（`commitRewards()`）
- 画面左上に「ステージ{S} - {s}/10」（ボス戦は「（ボス）」を併記）を常時表示し、今どのバトルかが分かるようにしている
- 各キャラ・敵の足元には、名前・実数値（例：`アカネ 180/220`）ではなく**細いHPゲージ**を表示する。実数値（`unit.hp`/`unit.maxHp`）は内部で保持したまま、表示はゲージの長さと色（50%より上＝緑、20〜50%＝黄、20%以下＝赤）だけで表現する（以前は名前＋実数値を表示していたが、キャラの表示と重なって見づらいとの指摘を受けて撤去、ユーザー確認済み）

## ターンの流れ（1バトルあたり）

1. 手番の順番を「仲間→敵」の順（配列の並び順）に固定し、以降この順を繰り返す（倒された対象の手番は即座にスキップ）
2. **仲間の手番**：画面下部に5つのボタン（一番左が「通常攻撃」、残り4つがそのキャラのスキル）を表示する。アイコンは[共通UIボタン素材](../ui-buttons.md)・[スキルデータ](../skills.md)（`lib/skills-info.ts`）から、手番中のキャラに応じて動的に切り替える
   - スキルは解放状況（[skills.md](../skills.md#スキルの解放強化スキルポイント)、キャラクター画面の「スキル」で操作）とCT（クールタイム、下記）の両方を満たしたものだけタップ可能。未解放は🔒アイコン、CT中は残りターン数（自分の手番基準）を数字で重ねて表示し、いずれもタップ不可（`disabled`）にする
   - CTは「自分の手番が何回回ってきたか」で数え、ステージ内の10連戦をまたいで持ち越し、ステージ開始（S-1）時のみリセットする（HPの持ち越しと同じ扱い）
3. 「通常攻撃」または使用可能なスキルをタップすると、以下の順で演出する（対象の選び方はスキルの`target`による：敵単体はランダム1体、敵全体は生存中の敵全員、味方1体の回復は最もHP割合が低い生存中の味方）
   1. 攻撃するキャラが1歩前に踏み出す
   2. 攻撃ポーズの画像に切り替わる（`battleAttack`）
   3. ダメージ計算（下記）を行い、対象がダメージポーズの画像に切り替わる（`battleDamage`）とともにHPを減算（`hits`が2以上のスキルは同じ対象に連続ヒット）
   4. 対象の頭上あたりに実際のダメージ量（会心時は「会心!」も併記）がフェードイン→少し表示→フェードアウトする。回復スキルは同じ場所に緑色で「+回復量」を表示する
   5. 対象が通常ポーズ（`battleIdle`）に戻る
   6. 攻撃したキャラも通常ポーズに戻り、元の位置まで下がる
   - 支援スキルは対象が味方全体のため上記の対象向け演出は行わず、発動メッセージのみ短く表示してバフを付与する（付与されたバフは、バフを受けた側の自分の手番を基準に指定ターン数だけ持続する）
   - 妨害効果を持つスキル（お静かに／蔦縛りの矢）は、命中した敵の次の手番を1回封じる（封じられた側は「動けない！」と表示されて行動をスキップする）
4. **敵の手番**は同じ演出を自動で行う（対象はランダムな生存中の仲間、常に通常攻撃相当）。プレイヤー操作は不要。妨害効果を受けている場合は仲間と同様に行動をスキップする

## ダメージ計算式

[combat.ts](../../../lib/combat.ts)に実装。詳細はadventure-system.mdの「ダメージ計算式」参照。

```
実効攻撃力 = 攻撃力 ×（1＋攻撃力バフ） + スキル基礎値（通常攻撃は0）
基礎ダメージ = 実効攻撃力 × 100 / (100 + 防御力 ×（1＋防御力バフ）)
会心判定 = 乱数 < 10% + 会心率バフ
最終ダメージ = round( 基礎ダメージ × 属性倍率 × (会心判定 ? 150% : 100%) )　※最低1
```

属性相性表がまだ未定のため、属性倍率は一旦なし（常に×1.0固定、ユーザー確認済み。`getElementMultiplier()`のみ実装しておき、表が決まり次第中身だけ差し替える）。通常攻撃は属性を持たない（常に属性倍率1.0固定）のに対し、スキルは各自の属性（[skills.md](../skills.md)参照）を持つ。装備（アーティファクト）による会心率・会心ダメージの上乗せ、支援スキルによる一時バフはいずれも実装済み（[items.md](../items.md#装備によるステータス加算)参照）。

## 実装上の注意（ハマりどころ）

- 攻撃演出はPromiseチェーン（`await`を挟んだ一連の`setTimeout`）で、1コマずつ状態を更新しながら進めている。**`requestAnimationFrame`は使わないこと。** ブラウザのタブが非表示（バックグラウンド）になっているとrAFのコールバックが呼ばれず、演出が永久に止まってしまう不具合が実際に発生した（`setTimeout`ベースの待機に置き換えて解消）
- 万一ターン進行中に例外が発生した場合、無言のまま画面が固まらないよう「敗北」扱いにしてホーム画面へ戻すフォールバックを入れている
- 10バトル分の進行は`playStage()`内のforループ＋`await runBattleLoop()`で順に処理している。仲間のHP・生存状態は`unitsRef.current`から`side === "ally"`のものを毎バトル後に取り出して次のバトルへ引き継ぐ
