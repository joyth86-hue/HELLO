# 戦闘画面・動作確認版（`/games/game1/battle`）

実装: [app/games/game1/battle/page.tsx](../../../app/games/game1/battle/page.tsx)

## 概要

[戦闘画面の配置設計](./battle.md)（仲間・敵を3体ずつ左右対称に配置するレイアウト）を、実際に**ターン制で通常攻撃だけを一巡させて動作確認する**ための実装。本実装ではなく、まずは「動きの流れ」を試すためのテスト版という位置づけ。下部ナビゲーションバー（[bottom-nav.md](./bottom-nav.md)）の管理下には無い、独立した画面（マップ/ショップ/冒険/仲間/バッグの5タブ画面とは別のルート）。

## 入り口（仮）

[ステージ選択画面](./stages.md)（`/games/game1/stages`）の各ステージから、`/games/game1/battle?stage=<ステージ番号>`という形で遷移してくる。ただし現状、`stage`パラメータは**勝利時に`maxClearedStage`を更新する（＝ステージ進行・キャラクター解放の動作確認をするため）にしか使っておらず**、敵構成・背景・10バトル連戦といった本来のステージごとの中身にはまだ反映されない（常に下記の仮データで1回だけ戦う）。

## テスト用データ（本番の編成・敵構成とは無関係）

- 仲間：`c01`（アカネ）・`c02`（カエデ）・`c03`（コユキ）の3体固定
- 敵：`e01`（こどもゴブリン）・`e02`（ゴブリン兄貴）・`e03`（古びたクマさん）の3体固定
- 双方ともHP 200固定、攻撃力は一律100（2発で撃破できる、すぐに決着がつく数値）
- 背景は`f01_sougen_hiru.png`を使用
- パーティ編成・敵の出現テーブル（[lib/battle-stages.ts](../../../lib/battle-stages.ts)）とは連携しておらず、`app/games/game1/battle/page.tsx`内に直接ハードコードしている

## 配置

[battle.md](./battle.md)で検討したレイアウトをそのまま使用。仲間は左側・敵は右側、上から`top: 42% / 55% / 68%`、幅16%で左右対称。

## ターンの流れ

1. 開始時に手番の順番を「仲間3体→敵3体」の順で固定し、以降この順を繰り返す（倒された対象の手番は即座にスキップ）
2. **仲間の手番**：画面下部に5つのボタン（一番左が「通常攻撃」、残り4つがそのキャラのスキル）を表示する。アイコンは[共通UIボタン素材](../ui-buttons.md)・[スキルデータ](../skills.md)（`lib/skills-info.ts`）から、手番中のキャラに応じて動的に切り替える。**現状は通常攻撃のみ実装済みで、スキル4つは画像を並べているだけの無効ボタン（`opacity-40`）**。スキルの解放状況（初期は1つのみ→スキルポイントで解放）もまだ無いため、常に4枠とも表示している（[skills.md](../skills.md)の「スキル解放について」参照）
3. 「通常攻撃」をタップすると、生存している敵からランダムに1体を対象に選び、以下の順で演出する
   1. 攻撃するキャラが1歩前に踏み出す
   2. 攻撃ポーズの画像に切り替わる（`battleAttack`）
   3. 対象がダメージポーズの画像に切り替わる（`battleDamage`）とともにHPを減算
   4. 対象の頭上あたりに「-100」のダメージ表記がフェードイン→少し表示→フェードアウトする
   5. 対象が通常ポーズ（`battleIdle`）に戻る
   6. 攻撃したキャラも通常ポーズに戻り、元の位置まで下がる
4. **敵の手番**は同じ演出を自動で行う（対象はランダムな生存中の仲間）。プレイヤー操作は不要
5. 敵が全滅したら「勝利！」、仲間が全滅したら「敗北…」を画面中央に表示し、約1.8秒後に自動でGame 1ホーム画面（`/games/game1/home`）に戻る
   - 「勝利！」の場合、`maxClearedStage`を`max(現在値, 渡されたstage番号)`で更新する（[adventure-system.md](../adventure-system.md)参照）

## 実装上の注意（ハマりどころ）

- 攻撃演出はPromiseチェーン（`await`を挟んだ一連の`setTimeout`）で、1コマずつ状態を更新しながら進めている。**`requestAnimationFrame`は使わないこと。** ブラウザのタブが非表示（バックグラウンド）になっているとrAFのコールバックが呼ばれず、演出が永久に止まってしまう不具合が実際に発生した（`setTimeout`ベースの待機に置き換えて解消）
- 万一ターン進行中に例外が発生した場合、無言のまま画面が固まらないよう「敗北」扱いにしてホーム画面へ戻すフォールバックを入れている
