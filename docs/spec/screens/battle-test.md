# 戦闘画面（`/games/game1/battle`）

実装: [app/games/game1/battle/page.tsx](../../../app/games/game1/battle/page.tsx)

## 概要

[戦闘画面の配置設計](./battle.md)（仲間・敵を3体ずつ左右対称に配置するレイアウト）を使った、**ステージ内10バトル連戦（`S-1`〜`S-10`）の本実装**。詳細ルールは[adventure-system.md](../adventure-system.md)参照。下部ナビゲーションバー（[bottom-nav.md](./bottom-nav.md)）の管理下には無い、独立した画面（マップ/ショップ/冒険/仲間/バッグの5タブ画面とは別のルート）。

数値（ステージ係数・敵の基礎ステータス・レベル成長・必要経験値カーブなど）はすべて仮で、後から係数を書き換えるだけで調整できる形にしている（[adventure-system.md](../adventure-system.md)参照）。

## 入り口

[ステージ選択画面](./stages.md)（`/games/game1/stages`）の各ステージから、`/games/game1/battle?stage=<ステージ番号>`という形で遷移してくる。

## パーティ・敵の生成

- **仲間**：`Game1SaveData.activePartyIds`（実際の編成、1〜3人）をそのまま使う。各キャラのHP/攻撃力/防御力は、そのキャラの現在レベル（[character-growth.ts](../../../lib/character-growth.ts)の`getCharacterStatsAtLevel`）に、装備中のアイテムによる加算（[item-effects.ts](../../../lib/item-effects.ts)の`calculateEquipmentBonus`/`applyEquipmentBonusToStats`）を乗せて算出する。会心率・会心ダメージの装備加算も同様に、通常攻撃のダメージ計算に反映される
- **敵**：ステージ番号から出現パターン（4色ローテーション、[enemy-scaling.ts](../../../lib/enemy-scaling.ts)の`pickRandomEnemyFromPattern`）を決め、そこからランダムに選ぶ。`S-1`〜`S-9`は3体、`S-10`（ボス）は1体（中央スロットに配置）。ステータス（HP/攻撃力/防御力）は「基礎値 × ステージ係数（`stageCoefficient`、2次関数カーブ）× 個体差（±10%、バトルごとに再抽選）」、経験値だけは別の緩やかな係数（`expCoefficient`、線形）を使う。ボスだけ追加でステータス×1.6・経験値×3
- **背景**：ステージ番号から`getFieldImagePathForStage()`で1ステージ＝1背景を固定で割り当てる（`f01`〜`f10`を10刻みで繰り返し）

## 10バトル連戦の進行

- `S-1`開始時に仲間は全員全回復した状態で始まり、そのステージを抜けるまでHPは持ち越される（敵は毎バトル新規生成）
- 1バトルごとに、生存している敵が全滅したら次のバトル（`S-s+1`）へ自動で進む（ステージ選択画面には戻らない）
- 仲間が全滅した場合：そのステージは未クリアのまま（`maxClearedStage`は更新しない）だが、**それまでに完全にクリアしたバトル分の経験値・ドロップ、および全滅した瞬間のバトルで倒せた敵の分の経験値**は`expPoints`・`inventory`に加算してから結果フレーム（下記）を表示する（次に挑む時は必ず`S-1`から）
- `S-10`（ボス）を撃破した場合：そのステージ内で倒した敵の経験値合計を`expPoints`に加算し、`maxClearedStage`を更新して保存。**スキルポイント**も固定量（`SKILL_POINTS_PER_STAGE_CLEAR`、[skills.md](../skills.md#スキルの解放強化スキルポイント)参照）を`skillPoints`に加算する（全滅時の部分回収には含まれない、クリア時のみ）。ドロップしたアイテム（[lib/item-drop.ts](../../../lib/item-drop.ts)、通常バトル3%／ボス戦5%でバトルごとに独立抽選）も`inventory`に加算する。両者で報酬の反映処理は共通（`commitRewards()`）
- **デイリーミッション**（[game1-home.md](./game1-home.md#デイリーミッション)参照）の進捗もここで加算する：勝利したサブバトルの数（全滅・クリア問わず、生き残って倒しきったバトルの数）と、ステージクリアなら+1。実装は`lib/daily-missions.ts`の`addBattleWins()`/`addStageClear()`

## 結果フレーム（クリア・全滅）

以前は画面中央に文字だけを数秒間表示して自動でホームへ戻る作りだったが、**中央にカード状のフレームを表示し、タップで進行する**形に変更した（[Artifactで検討したモック](https://claude.ai/code/artifact/545223eb-d5fe-4e77-abd3-3c868f908fe1)を元に、ユーザー確認済み）。自動遷移のタイマーは廃止し、必ずタップして閉じるまで画面に留まる。

- フレームは画面中央、不透明な濃い紫（`#241f47`）のカード（`rounded-2xl`、`rgba(201,195,255,0.5)`の縁、ドロップシャドウ）。背景を透過させると読みにくいとの指摘を受け、あえて不透明にしている
- **基本メッセージ（1ページ目）**：以下を上から順に、値が0（またはアイテムなし）の行は表示しない
  1. 見出し：「ボスを倒した！」（クリア、金色）／「全滅してしまった…」（敗北、くすんだローズ）
  2. サブテキスト：「次のステージに進もう。」／「訓練して出直そう。」
  3. 獲得経験値：`{expEarned}pt`
  4. 獲得スキルpt：`{skillPointsEarned}pt`（クリア時のみ発生しうる）
  5. 獲得アイテム（見出しのみ）
  6. ドロップしたアイテムのアイコン一覧：レア度に応じた色（[items.md](../items.md#アイテム効果の確認詳細ポップアップ)と共通の`RARITY_COLOR`）で縁取った大きめのアイコン（`h-16 w-16`）を並べる。個体数が2以上なら右下に`×N`バッジ。ドロップの喜びが薄いという指摘を受け、以前の小さいアイコン（`h-9 w-9`）から拡大した（ユーザー確認済み）
     - 各アイコンはタップ可能で、[items.md](../items.md#アイテム効果の確認詳細ポップアップ)の詳細ポップアップ（アイコン・名前・レア度・実際の効果一覧）をその場で開ける。見出しに「（タップで効果を確認）」と添えて操作できることを示す。ポップアップを閉じても結果フレーム自体は閉じない
  - バッグの所持数上限で受け取れなかった分があれば、末尾に注記を表示する
- **個別メッセージ（2ページ目以降）**：そのステージのボスを初めて撃破した時にだけ発生する追加メッセージ（下記参照）。1件につき1ページで、中央の丸バッジ＋見出し＋説明文を表示する
- ページが2つ以上ある場合のみ、フレーム下部にページドット（●○）を表示する。タップのたびに次のページへ進み、最後のページでタップするとホーム画面へ戻る
- 個別メッセージが無い場合（通常バトル敗北時、または個別メッセージを持たないボス撃破時）は基本メッセージが最初から最後のページを兼ねる＝1回タップで閉じる

### 個別メッセージの仕組み

実装：`app/games/game1/battle/page.tsx`の`getIndividualMessagesForStageClear()`（候補の算出）、`Game1SaveData.shownIndividualMessageIds`（表示済み管理）。

- ステージのボス（S-10）を撃破した時だけ判定する。候補は現状「そのステージクリアで仲間が解放される場合」（[game1-data.ts](../../../lib/game1-data.ts)の`CHARACTER_UNLOCK_STAGE`）の1種類で、「○○が仲間になった！」＋「「仲間」タブから編成に加えられます。」を表示する。今後「〇〇機能が解放された」系のメッセージを追加する場合も、`getIndividualMessagesForStageClear()`に候補を足していくだけでよい
- 各メッセージには固定ID（例：`character-unlock:c03`）を持たせ、一度表示したIDは`shownIndividualMessageIds`に記録する。**同じステージを周回して再度ボスを倒しても、既に表示済みのメッセージは出さない**
- 画面上半分（キャラ・敵より上）は背景のみで余白になっているため、そこに大きめの文字で「Stage {S}」＋一回り小さく「Battle {s}」（ボス戦は末尾に" (Boss)"を併記）を中央寄せで表示している（以前は左上に小さいピルで「ステージ{S} - {s}/10」と表示していたが、余白を活かして目立たせてよいとの指摘、および分数表記の下段が小さすぎて見えないとの指摘を受けて変更、ユーザー確認済み。この2行だけ英語表記なのもユーザー指定）
- 各キャラ・敵の足元には、名前・実数値（例：`アカネ 180/220`）ではなく**細いHPゲージ**を表示する。実数値（`unit.hp`/`unit.maxHp`）は内部で保持したまま、表示はゲージの長さと色（50%より上＝緑、20〜50%＝黄、20%以下＝赤）だけで表現する（以前は名前＋実数値を表示していたが、キャラの表示と重なって見づらいとの指摘を受けて撤去、ユーザー確認済み）

## ターンの流れ（1バトルあたり）

1. 手番の順番を「仲間→敵」の順（配列の並び順）に固定し、以降この順を繰り返す（倒された対象の手番は即座にスキップ）
2. **仲間の手番**：画面下部に5つのボタン（一番左が「通常攻撃」、残り4つがそのキャラのスキル）を表示する。アイコンは[共通UIボタン素材](../ui-buttons.md)・[スキルデータ](../skills.md)（`lib/skills-info.ts`）から、手番中のキャラに応じて動的に切り替える
   - スキルは解放状況（[skills.md](../skills.md#スキルの解放強化スキルポイント)、キャラクター画面の「スキル」で操作）とCT（クールタイム、下記）の両方を満たしたものだけタップ可能。未解放は🔒アイコン、CT中は残りターン数（自分の手番基準）を数字で重ねて表示し、いずれもタップ不可（`disabled`）にする
   - CTは「自分の手番が何回回ってきたか」で数え、ステージ内の10連戦をまたいで持ち越し、ステージ開始（S-1）時のみリセットする（HPの持ち越しと同じ扱い）
3. 「通常攻撃」または使用可能なスキルをタップすると、以下の順で演出する（対象の選び方はスキルの`target`による：敵単体はランダム1体、敵全体は生存中の敵全員、味方1体の回復は最もHP割合が低い生存中の味方）
   1. 攻撃するキャラが1歩前に踏み出す
   2. 攻撃ポーズの画像に切り替わる（`battleAttack`）
   3. ダメージ計算（下記）を行い、対象がダメージポーズの画像に切り替わる（`battleDamage`）とともにHPを減算（`hits`が2以上のスキルは同じ対象に連続ヒット）
   4. 対象の頭上あたりに実際のダメージ量がフェードイン→少し表示→フェードアウトする。符号（-/+）や「会心!」の文字は付けず、色だけで区別する（**通常ダメージ＝白／会心ダメージ＝赤／回復＝緑**、いずれも黒フチ縁取り＋太字。回復は数値の後ろに「回復」の文字を添える）。何パターンかの見せ方をArtifactで比較して、ユーザーが選んだもの（太字＋縁取り、コード名「B」）を採用している
   5. 対象が通常ポーズ（`battleIdle`）に戻る
   6. 攻撃したキャラも通常ポーズに戻り、元の位置まで下がる
   - **敵全体スキルは、対象ごとにこの一連の動作を繰り返すのではなく、1回の踏み込み・攻撃ポーズで生存中の敵全員へ同時にダメージを与える**（`resolveAoeHit()`）。ダメージ計算とダメージポップアップの表示は対象ごとに独立させつつ`Promise.all`でまとめて並行実行することで、複数の敵の頭上に同時にダメージ数値が浮かぶ見た目にしている。以前は対象を1体ずつ順番に攻撃していたが、「一気にすべての敵に攻撃するようにしてほしい」との指摘を受けて変更した（ユーザー確認済み）。`hits`が2以上の敵全体スキルがある場合は、ヒットのたびにこの同時攻撃を繰り返す（現状はどの敵全体スキルも`hits:1`）
   - 支援スキルは対象が味方全体のため上記の対象向け演出は行わず、発動メッセージのみ短く表示してバフを付与する（付与されたバフは、バフを受けた側の自分の手番を基準に指定ターン数だけ持続する）
   - 妨害効果を持つスキル（お静かに／蔦縛りの矢）は、命中した敵の次の手番を1回封じる（封じられた側は「動けない！」と表示されて行動をスキップする）
4. **敵の手番**は同じ演出を自動で行う（対象はランダムな生存中の仲間、常に通常攻撃相当）。プレイヤー操作は不要。妨害効果を受けている場合は仲間と同様に行動をスキップする

## ダメージ計算式

[combat.ts](../../../lib/combat.ts)に実装。詳細はadventure-system.mdの「ダメージ計算式」参照。

```
実効攻撃力 = 攻撃力 ×（1＋攻撃力バフ） + スキル基礎値（通常攻撃は0）
基礎ダメージ = 実効攻撃力 × 100 / (100 + 防御力 ×（1＋防御力バフ）)
会心判定 = 乱数 < 10% + 会心率バフ
最終ダメージ = round( 基礎ダメージ × 属性倍率 × (会心判定 ? 150% : 100%) )　※最低1
```

属性倍率は[roster.md](../roster.md#属性の相性弱点耐性)の相性の輪（水→炎→氷→草→岩→水）に基づき、隣接する属性同士のみ1.25倍（有利）／0.75倍（不利）、それ以外（2つ離れている・同属性）は1.0倍（`lib/combat.ts`の`getElementMultiplier()`、ユーザー確認済み）。通常攻撃は属性を持たない（常に属性倍率1.0固定）のに対し、スキルは各自の属性（[skills.md](../skills.md)参照）を持つ。敵は通常攻撃相当の行動のみでスキルを持たないため、この倍率が実際に効くのは現状「プレイヤーのスキル攻撃→敵」の向きのみ。装備（アーティファクト）による会心率・会心ダメージの上乗せ、支援スキルによる一時バフはいずれも実装済み（[items.md](../items.md#装備によるステータス加算)参照）。

## 実装上の注意（ハマりどころ）

- 攻撃演出はPromiseチェーン（`await`を挟んだ一連の`setTimeout`）で、1コマずつ状態を更新しながら進めている。**`requestAnimationFrame`は使わないこと。** ブラウザのタブが非表示（バックグラウンド）になっているとrAFのコールバックが呼ばれず、演出が永久に止まってしまう不具合が実際に発生した（`setTimeout`ベースの待機に置き換えて解消）
- 万一ターン進行中に例外が発生した場合、無言のまま画面が固まらないよう「敗北」扱いにしてホーム画面へ戻すフォールバックを入れている
- 10バトル分の進行は`playStage()`内のforループ＋`await runBattleLoop()`で順に処理している。仲間のHP・生存状態は`unitsRef.current`から`side === "ally"`のものを毎バトル後に取り出して次のバトルへ引き継ぐ
- 攻撃時の「1歩前に出る」演出（`translateX`によるステップ）は、**キャラの画像だけに掛ける**（HPゲージは掛けない）。ユニットのスロット用`<div>`に直接transformを掛けていた頃は、画像もHPゲージも一緒に前後へ動いてしまっていた（ユーザー確認済みで不要と判断）。今は画像を包む内側の`<div>`にだけtransformを掛け、HPゲージはその外側（同じ親の兄弟要素）に置くことで、常に位置が固定されるようにしている
- 手番中インジケータ（頭上の黄色い点滅ドット）は、指示が無かったため撤去した（過去にはこれが通常フローに置かれていたことで、表示/非表示の切り替わりの度に下の画像・HPゲージの位置がガクッとずれる不具合も起きていた）
- 演出のテンポは`BATTLE_TEMPO_MULTIPLIER`（現在2.0＝2倍速。1.5→2.0に調整済み）で一括調整できる。攻撃演出・ターン切り替えなどの待ち時間は素の`wait(ms)`ではなく`tempoWait(ms)`（＝`wait(ms / BATTLE_TEMPO_MULTIPLIER)`）を使うことでこの倍率がまとめて掛かる。ただし`showPopup()`内の`wait(20)`（CSSトランジション開始待ちの技術的な最小待ち）だけは対象外で、素の`wait()`のまま
