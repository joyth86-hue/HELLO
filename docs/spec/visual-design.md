# ビジュアルデザイン方針

現時点では仮のデザイン。今後、実際のゲームコンテンツに合わせて見直す前提。

## 配色・ボタン方向

初期は「やさしいパステル」（淡いミント背景）で開始したが、「あきくんゲームズ」時代の名残で世界観に合っていなかったため、**ダーク系＋流れる背景模様**に変更した（下記「背景（流れる文字パターン）」参照）。ボタンなどの「ステッカー風」デザイン自体は変えず、背景がダークになったことで色味だけ調整している。

- 背景：ダーク系グラデーション `#14132a` 〜 `#1c1a3a`（`--background`、[app/globals.css](../../app/globals.css)。Tailwindのユーティリティクラスとしては `bg-background`）＋[流れる文字パターン](#背景流れる文字パターン)
- 基本の文字色：明るいオフホワイト（`#f4f1ff` 相当、`--foreground`）
- ボタン（有効・押せるもの）：白地＋黒の太め（2px）縁取り＋オフセット影（ぼかし無し、右下にずらしただけの「ステッカー風」）は据え置き。影の色だけ、黒背景で沈んで見えなくなるため紫系 `#4a3f86` に変更。押すとボタン自体が影の位置まで沈み込み、影が小さくなることで「物理的に押した」感触を出す。実装：[lib/ui.ts](../../lib/ui.ts) の `stickerButton`
- ボタン（無効・押せないもの、例：メニューのComing soon）：薄いグレー背景＋グレー文字、影や縁取りなし（`stickerButtonDisabled` または個別のグレー系クラス）
- カード類（ステータスカード、アイテムカードなど）：半透明の白（`rgba(255,255,255,0.06〜0.09)`）＋薄い紫の縁取り（`rgba(201,195,255,0.35〜0.55)`）のガラス風。キャラクター確認画面の額縁やバッグ画面の詳細シートのようにクリーム色 `#fffaf0` の紙・額縁を模したパーツは、ダーク背景に映えるためそのまま維持

OS・ブラウザのダークモード設定に関わらず、常にこの配色（固定）で表示する。ゲームとしてのブランド・見た目を統一するため。

パステルミント案を含む比較検討した他の案は不採用。

## 背景（流れる文字パターン）

ホーム画面・キャラクター確認画面・バッグの中身画面の3画面で、「hiro games」の文字が右上から左下へ斜めに流れ続ける背景を使っている。実装は[components/GameBackground.tsx](../../components/GameBackground.tsx)を各画面のルート要素の最初の子として置く形（詳細はコンポーネント内のコメント参照）。

- ダークグラデーションのベース層（インラインスタイルのCSSグラデーション）
- 「hiro games」の文字を敷き詰めた模様の層：[public/backgrounds/pattern-hiro-games.svg](../../public/backgrounds/pattern-hiro-games.svg)（210×85pxのシームレスタイル、22度傾けた文字を段ごとに150pxずらして配置）を`background-repeat`で敷き詰め、`animate-bg-drift`（[app/globals.css](../../app/globals.css)）で1周7秒のループアニメーションをかけている
- **文字の傾きと流れる向きは同じ角度に揃えている**（ユーザー指摘により調整済み。ズレていると違和感が出る）
- 内側に軽いビネット（`shadow-[inset_...]`）をかけて中央を見やすくしている
- `prefers-reduced-motion: reduce`が有効な環境ではアニメーションを止める

検討時にArtifactで作ったモックアップ：[背景デザイン案](https://claude.ai/code/artifact/214e7109-c50f-435e-a94e-a361cc4af896)（ホーム画面・バッグ画面のイメージ、傾き・ずらし幅・速度の調整もここで実施）。

ホーム画面のみ、この模様とは別に専用の背景イラストを使っている（詳細は[screens/game1-home.md](./screens/game1-home.md)参照）。

### キャラクター画面：キャラクターごとに背景全体の色を変える

[キャラクター確認画面](./screens/character-view.md)だけは、表示中のキャラクターごとに**背景のベースカラーそのもの**を丸ごと差し替えている。他の画面共通の濃紺〜紫のグラデーション部分自体をキャラごとの色（例：アカネなら背景全体がワイン・ローズ系）に置き換え、その上を「hiro games」の文字が同系色で流れる、という見え方にしている。中央上部にうっすら光を足すだけの演出（アクセントカラー程度の変更）では「別の色の背景」には見えない、という指摘を受けて、ベースグラデーション自体を差し替える方式に変更した。

実装：`GameBackground`に`baseGradient`（ベースのグラデーションCSSをまるごと差し替え）、`glowColor`（中央上部に足すうっすらした光の色）、`textColor`（流れる文字の色）の3つを渡す（[components/GameBackground.tsx](../../components/GameBackground.tsx)）。画像ファイルを複数用意する必要はなく、いずれもCSSの色指定のみで実現している。「hiro games」の文字パターン画像（[public/backgrounds/pattern-hiro-games.svg](../../public/backgrounds/pattern-hiro-games.svg)）自体は共通の1種類のままで、`mask-image`として使い、その形（アルファ）だけを借りて任意の`background-color`で塗り直す方式（SVG自体のfill色は使わないので、指定した色がそのまま出る）。キャラクター側の指定は[app/games/game1/(main)/character/page.tsx](<../../app/games/game1/(main)/character/page.tsx>)の`CHARACTER_BG_COLORS`。

キャラクター自身の衣装の色と背景が被って埋もれないよう、あえて補色寄りの色を選んでいる。

| キャラ | 衣装の色味 | 背景ベース（例） | 流れる文字の色 |
| --- | --- | --- | --- |
| アカネ | 赤・オレンジ系（炎） | ワイン・ローズ系のダークグラデーション | ピンク `#ff9ec9` |
| カエデ | 淡い緑・白系（草） | 暖色（アンバー・ブラウン）系のダークグラデーション | 明るいアンバー `#ffcf8a` |
| コユキ | 青・白系（氷） | マゼンタ・紫系のダークグラデーション | 明るい紫（マゼンタ寄り） `#d9a8ff` |
| サユミ | 茶・緑系（草） | 寒色（ティール）系のダークグラデーション | 明るいティール `#8ce9e0` |

各グラデーションの正確な色コードは`CHARACTER_BG_COLORS`（実装ファイル）を正とする。全体の明るさ・彩度は元の濃紺グラデーションと揃え、「ダークで少し遊び心のあるトーン」という[全体の配色方針](#配色ボタン方向)から外れすぎないようにしている。

キャラクター切り替え時は`transition`でふわっと色が変わる（ベース・グロー・文字色とも0.5秒）。「hiro games」の文字パターン画像自体は共通の1種類のまま、その上に乗る色（`baseGradient`/`glowColor`/`textColor`）だけがキャラクターごとに切り替わる。

## アプリアイコン（ホーム画面に追加した際のアイコン）

iPhone・Androidで「ホーム画面に追加」した際に表示されるアイコン、およびブラウザタブのファビコンには、[app/icon.png](../../app/icon.png)（512×512）と[app/apple-icon.png](../../app/apple-icon.png)（180×180、Appleのapple-touch-icon推奨サイズ）を使っている。どちらもNext.jsの[ファイル規約](https://nextjs.org/docs/app/api-reference/file-conventions/metadata/app-icons)（`app/`直下に`icon.png`・`apple-icon.png`を置くと自動で`<head>`にタグが追加される）に沿って配置しているだけで、コード側の設定は不要。

元データは`サンプル画像/app_icon.png`（1024×1024、アカネの顔アップイラスト）。`sharp`でそれぞれのサイズにリサイズして`app/`直下にコピーしている。差し替える場合は同様に`サンプル画像/`に新しい元画像を置いてもらい、リサイズして`app/icon.png`・`app/apple-icon.png`を上書きする。

## セーフエリア（ノッチ・ステータスバー）対応：試した末に撤去

iPhoneで画面最上部の時計・電波・充電残量が表示されるエリアの背景が塗られず帯状に空いて見える問題があり、一時期`viewportFit: "cover"`＋`metadata.appleWebApp`（`capable: true` / `statusBarStyle: "black-translucent"`）を設定してノッチ分の領域までページの背景を届かせる対応をしていたが、**実機（iPhone）で「画面全体が上にずれ、本来は無いはずの余白が画面下部に出る」という副作用が発生したため撤去した**（`app/layout.tsx`の`viewport`から`viewportFit`を削除、`metadata.appleWebApp`も削除）。

- ノッチ・ステータスバー周りの帯（背景が塗られていない）は、現状ユーザー側の判断で許容している。「上部に余白がある」方が「見た目全体がずれる」より好ましいという判断
- 各画面に追加していた`padding-top: env(safe-area-inset-top)`（ホーム画面右上パネル、キャラクター画面の名前ヘッダー、ステージ選択・バッグ画面の見出し、戦闘画面上部のピルなど）は、`viewportFit: "cover"`を外すと`env(safe-area-inset-top)`が常に`0px`扱いになるため実質無害（コードは残っているが効果が無いだけ）。今後同様の対応を再検討する場合は、まずこのファイルの記録を確認すること
- 画面の高さを`h-screen`ではなく`h-[100dvh]`にした対応（下記）は、この件とは独立した別の不具合修正であり、これは維持している

### 100vhでの縦スクロール不具合の修正（維持中）

上記のノッチ対応（`viewportFit: "cover"`）を試していた際、ホーム画面など`min-h-screen`/`h-screen`（`100vh`）を使っていた画面で、実際には見えていないはずの余白分だけ画面が縦スクロールできてしまう不具合が出た（iOS Safariで`100vh`がアドレスバー等を含めた最大サイズとして扱われ、実際に見えている範囲より大きくなることがあるため）。対応として、各画面のルート要素の高さは`h-screen`ではなく`h-[100dvh]`（動的ビューポート高さ）を使うようにした。`dvh`は実際に見えている範囲に追従するため、この種のズレが起きない。この修正自体は`viewportFit: "cover"`の有無に関わらず有効なため、上記のノッチ対応を撤去した後もそのまま維持している。

### ページ全体のラバーバンド（バウンド）対策（維持中）

スマホでスワイプした際にページ本体（html/body）がバウンドして上下に動いてしまう問題への対応として、[app/globals.css](../../app/globals.css)の`html, body`に`overscroll-behavior: none`と`overflow: hidden`を指定している。これも上記のノッチ対応とは独立した対策で、そのまま維持している。バッグ画面のタブ横スクロールや装備選択シートの内部スクロールなど、要素個別の`overflow-auto`には影響しない。

## フォント・見た目のトーン

- 手書き感のあるロゴと、ステッカーのような立体感のあるボタンで、シンプルながら少し遊び心のあるトーンにする
- 角丸のボタン・カードを使用し、硬すぎない印象にする

## ロゴ（「あきくんゲームズ」ブランド・現在未使用）

複数ゲームをまとめるハブ画面があった頃に、そのブランド名「あきくんゲームズ」用に作成したロゴ。ハブ画面自体を廃止した（[screens/start.md](./screens/start.md)参照）ため、現在はどこにも表示されていないが、実装は残してある。

- ロゴタイプ：「まる文字ポップ」案で確定（Google Fonts の `Hachi Maru Pop`）。手書きの丸っこいポップな文字。
- 実装：[components/Logo.tsx](../../components/Logo.tsx)。文字ごとに角度・縦位置を少しずつ決まった計算式でずらし、手書きの「がたがた」感を出している（乱数ではないのでサーバー・クライアントで見た目が一致する）。
- フォント自体は `app/layout.tsx` の `<head>` で Google Fonts の `<link>` から読み込んでいる（`next/font/google` は日本語文字を含むフォントの扱いが不安定なため見送り）。
- 検討時に他4案（ゆるふわ／マーカー太字／筆ペン／ラフスケッチ二重線）も作成したが、今回は不採用。
- `animate-fade-up`（[app/globals.css](../../app/globals.css)）というフェード＋浮き上がりの演出クラスも、このロゴ表示のために作ったもので、同様に現在未使用。

## 今後

各ゲームのジャンルに応じて、ゲーム内画面はここで定めた全体トーンから外れた独自の配色を使う可能性がある。その場合はこのファイルに「共通UI（スタート・メニュー）の配色」と「ゲーム個別の配色」を分けて追記する。
