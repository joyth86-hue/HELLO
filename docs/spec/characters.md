# キャラクター素材

## 保存場所・命名規則

実際にアプリで使う画像は [public/characters/](../../public/characters/) に置く。

ファイル名: `c{キャラID2桁}_{種類}{連番2桁}.png`

- `t01` : 立ち絵（動かさない前提の一枚絵。詳細を綺麗に見せるためのもの）。**現在はキャラクター画面では使用していない**（下記の待機アニメーションに差し替え済み）。将来、詳細確認用の別画面などで使う可能性はあるためファイル自体は残している
- `d01` : 戦闘用ドット絵（3頭身、通常時）
- `d02` : 戦闘用ドット絵（3頭身、攻撃時）
- `d03` : 戦闘用ドット絵（3頭身、ダメージ時）

1キャラにつき上記4枚が基本セット。キャラが増える場合は `c02`, `c03`, ... と番号を増やす。

現在は `c01`〜`c04` の4キャラ分（計16枚）が揃っている。各キャラの名前・設定・ゲーム内での役割は未定（今後決める）。

### キャラクター画面用：ドット絵待機アニメーション

[public/characters/idle/](../../public/characters/idle/) に `c{キャラID2桁}_idle_sheet.png` として1キャラ1枚のスプライトシートを置いている。素材は外部の画像制作リポジトリ（`hirogames_images`、`CHARACTER_SCREEN_ASSETS.md`が引継ぎ入口）で作られたもので、1コマ486×810px・8列×5行・40コマ・100ms間隔（4秒ループ）という仕様で4キャラ共通。表示側の実装詳細は[screens/character-view.md](./screens/character-view.md)を参照。

## 画像の作り方

Claude自身は画像生成AIを持たないため、キャラクター素材は外部の画像生成AI（NijiJourneyなど）でユーザー側が生成し、`WebApp_game/サンプル画像/` フォルダに置いてもらう運用にしている。

- `サンプル画像/` フォルダの中身は消したり移動させたりしない（ユーザーの作業用フォルダのため）。新しい画像が追加されたら、`public/characters/` に**コピー**して使う
- `サンプル画像/` は `.gitignore` で除外しており、GitHubには上げない。実際にアプリで使う `public/characters/` 側だけをコミットする

## 画像の加工

- 戦闘用ドット絵（`d01`〜`d03`）は、生成された時点では白背景が焼き込まれているため、`sharp`（Next.jsが依存として持っているライブラリ）を使って白背景を透過に変換してから `public/characters/` に置いている。ゲーム内の背景色（パステルミント）に重ねても白い縁が出ないことを確認済み
  - **透過処理は「画像の外周から連結している明るい画素だけ」を透過するフラッドフィル方式で行うこと。** 単純に「明るさが閾値を超えた画素は全部透過」という判定をすると、キャラクター内部の白いハイライト（髪・肌・衣装の明るい部分）まで巻き込んで穴だらけになる事故が過去に発生した（c02, c03の白系衣装キャラで顔やドレスが透けてしまった）。外周からのフラッドフィルなら、外周とつながっていない内部の明るい画素は透過されずに残る
  - 透過処理後は、透明・半透明画素をマゼンタなど目立つ色に置き換えた診断画像を作って目視確認する（キャラクター内部にマゼンタが出ていないか＝穴が開いていないかのチェック）
- 立ち絵（`t01`）は複雑な描き込みがあり誤って絵を傷つけるリスクがあるため、現時点では背景透過をしていない（白背景のまま）。必要になれば同様の処理を検討する
