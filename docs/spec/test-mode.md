# テストモード（管理者用の全解放モード）

テストプレイをしやすくするための、合言葉で切り替える隠しモード。実装：[lib/test-mode.ts](../../lib/test-mode.ts)、[components/TestModeBadge.tsx](../../components/TestModeBadge.tsx)。

## 入り口

[Game 1ホーム画面](./screens/game1-home.md)右端の「プレゼント」アイコンをタップすると、「コードを入力」シートが開く。本来はギフトコード引き換え用の入り口だが、`lib/test-mode.ts`の`TEST_MODE_CODE`（現在は`HIROTEST`、大文字小文字は区別しない）と一致した場合だけ、テストモードのON/OFFが切り替わる（同じコードをもう一度入力するとOFFに戻る）。それ以外の文字列を入力した場合は「そのコードは使用できません」と表示するだけで、ギフトコード引き換え自体はまだ実装していない。

## 何が変わるか

テストモード中（`Game1SaveData.testMode === true`）は、以下の画面で表示・判定用のデータだけが「全解放」に差し替わる（`getEffectiveGame1Data()`）。

- [ステージ選択画面](./screens/stages.md)：`maxClearedStage`を`TEST_MODE_MAX_STAGE`（現在100）扱いにし、全ステージに挑戦できる
- [バッグの中身画面](./screens/bag.md)：`inventory`を全アイテム（`ITEM_BASE_INFO`全件、各1個）扱いにする
- [キャラクター確認画面](./screens/character-view.md)：上記のバッグ差し替えにより、4人全員のキャラクターが解放済み扱いになり（`maxClearedStage`が全解放扱いのため）、装備の選択候補にも全アイテムが並ぶ

テストモード中は、該当する画面の見えやすい位置に黄色い「テストモード中」バッジ（`TestModeBadge`）を表示する。

## 実データは書き換えない

`getEffectiveGame1Data()`は**読み取り専用のヘルパー**で、渡された`Game1SaveData`を書き換えずに「全解放済みの見た目のコピー」を新しく作って返すだけ。実際のセーブデータ（`maxClearedStage`・`inventory`・`activePartyIds`・`characterInvestedExp`など）はテストモードのON/OFFによって一切変更されない。書き込み処理（パーティ編成、装備、コード入力自体）は必ず元の（実際の）`Game1SaveData`に対して行うこと——`getEffectiveGame1Data()`の戻り値に対して`saveGame1Data()`を呼んではいけない。

このため、テストモードをOFFに戻すと、通常プレイの進行状況（クリア済みステージ・所持アイテム・経験値など）はそのまま元通り表示される。

## 既知の注意点

テストモード中に、実際には所持していないアイテム（全解放表示でのみ見えているアイテム）をキャラクターに装備させた場合、その装備の記録自体は実データ（`Game1SaveData.equipment`）に保存される。そのため、テストモードをOFFに戻すと、バッグには存在しないのにキャラクターの装備欄には残ったままになることがある（外せば解消する）。ユーザーに確認済みで、現状はこのまま許容する方針（今後、装備制限や自動解除を入れたくなったら検討する）。

## 今後

- 合言葉は`lib/test-mode.ts`の`TEST_MODE_CODE`を書き換えるだけで変更できる
- 本来のギフトコード引き換え機能（アイテム・通貨の付与）はまだ実装していない。実装する場合は、同じ「コードを入力」シートに判定ロジックを追加する形になる
