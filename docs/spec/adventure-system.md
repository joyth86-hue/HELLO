# 冒険システム設計（ステージ進行・成長・報酬）

「冒険に行く」から始まる、ステージ攻略・キャラクター解放・レベル成長・アイテムドロップ・ダメージ計算まわりの設計。数値の全体像（アイテムのレアリティ抽選テーブル、敵の強さ・経験値のステージ別テーブル、キャラクターのレベル別ステータス、ダメージ計算式）は下記Artifactにまとめてある。**このファイルはルール面の確定事項を記録し、Artifactの数値は今後Artifact側の更新に追従して差分を書く。**

検討時のArtifact: [冒険システム設計案](https://claude.ai/code/artifact/d3609ad6-4cd8-4556-aab9-92c2adb43a2a)

## ステージ構成

- 記法は`S-s`（S=ステージ番号1〜100、s=ステージ内バトル1〜10、s=10がボス戦）。IDは既存の[battle-stages.md](./battle-stages.md)の`bs{S}-{s}`形式を流用する想定（100まで扱うため3桁化が必要）
- 選べるステージ：クリア済みの全ステージ＋未クリアの最新1ステージのみ
- 1ステージ＝10バトル連戦。`S-1`〜`S-9`は敵3体、`S-10`（ボス）は敵1体。開始すると全滅かボス撃破まで自動で連戦が続く（ステージ選択画面には戻らない）
- HPは連戦中ずっと持ち越し。`S-1`開始時に全回復し、そのステージを抜けるまで回復なし
- 全滅したら、そのステージは未クリアのまま。次に挑む時は必ず`S-1`から再スタート。**ただし、そこまでに倒した敵の分の経験値・ドロップは持ち帰れる**（`maxClearedStage`だけは更新されない）。詳細は下記「アイテムドロップ」「経験値とレベル成長」参照
- `S-10`（ボス）撃破でステージクリア。クリア画面へ遷移し、`S+1`が新たに挑戦可能になる
- クリア済みステージは何度でも周回可能（経験値・アイテム集めのため）
- クリア画面：「ステージクリア」（全滅時は「敗北…」）表示＋その時点までの獲得経験値合計とドロップアイテム一覧をまとめて表示

## 敵の出現パターン・強さ・背景

- 敵の種類が少ないため、ステージごとに4パターン（ゴブリン系／クマ系／キノコ系／スライム系）を順に繰り返して割り当てる。詳細はArtifact参照
- 敵の強さ（HP/攻撃力/防御力）は「基礎値 × ステージ係数 ± 個体差」で決まる。個体差の幅はステージ単位で1つ（`S-1`〜`S-10`まで共通）
- **ステージ係数は2次関数カーブ（`1 + 0.02×(S-1) + 0.001736×(S-1)²`、ステージ100で約20倍）**。当初は複利（指数）カーブを試したが、終盤だけ急激に跳ね上がり、レベル上限（100）にぶつかった瞬間に詰みかける「崖」ができてしまったため2次関数に変更した。2次関数は「10ステージあたりの必要挑戦回数の伸び幅」自体がなだらかに直線的に増えていく性質があり、崖ではなく徐々にきつくなる曲線になる。武器合成やスキルなど「戦闘を楽にする」追加要素をまだ実装していない前提で、進行がしっかり歯ごたえのあるものになるよう線形よりだいぶ強めに設定している（ユーザー確認済みの仮数値。将来それらの要素が実装された段階で改めて調整する想定）。実装は[lib/enemy-scaling.ts](../../lib/enemy-scaling.ts)の`stageCoefficient()`
- **経験値だけは別の緩やかな係数（線形、`1 + (S-1) × 0.06`、ステージ100で約7倍）を使う**（`expCoefficient()`）。上記のステータス用係数と同じにすると、敵が強くなるほど経験値も同じ倍率で増えてレベルが常に敵の強さに追いつき続けてしまい、ステータス側を強めた意味が薄れるため意図的に分離した
- `S-10`（ボス）だけ追加のボス補正（ステータス×1.6、経験値×3）をかける
- 背景は1ステージ＝1背景固定。`fields.md`の10種類をステージ番号順に単純に繰り返す

## キャラクターの仲間解放

初期仲間はアカネ（`c01`）のみ。以下のステージをクリアすると新しい仲間が加入する（実装: [lib/game1-data.ts](../../lib/game1-data.ts)の`CHARACTER_UNLOCK_STAGE`）。

| キャラクター | 解放条件 |
| --- | --- |
| アカネ（c01） | 最初から仲間 |
| コユキ（c03） | ステージ3クリア |
| カエデ（c02） | ステージ6クリア |
| サユミ（c04） | ステージ9クリア |

## 編成（バトルに参加）

- 4人のうち、バトルに出撃できるのは最大3人。編成専用の画面は用意せず、[キャラクター確認画面](./screens/character-view.md)に「バトルに参加」チェックボックスを置くだけの簡易な形にしている
- 4人揃うまでは、新しく仲間になったキャラクターはデフォルトでチェックON（自動で編成に入る）。3人に達した後に4人目が仲間になった場合は自動では入れず、手動で入れ替える
- 実装：[lib/game1-data.ts](../../lib/game1-data.ts)の`Game1SaveData.activePartyIds`（`syncActivePartyWithUnlocks()`で新規解放キャラを自動追加）

## ダメージ計算式

Artifactの「2. ダメージ計算式（案）」を参照。要点：

```
基礎ダメージ = 攻撃力 × 100 / (100 + 防御力)
会心判定 = 乱数 < (10% + 装備の会心率)
倍率 = 属性倍率 × (会心判定 ? 150% + 装備の会心ダメージ : 100%)
最終ダメージ = round( 基礎ダメージ × 倍率 )　※最低1
```

属性相性の輪は[roster.md](./roster.md#属性の相性弱点耐性)参照（水→炎→氷→草→岩→水、隣接のみ有利1.25倍・不利0.75倍）。ブローチ（アーティファクト）の属性耐性ptは、この倍率にはまだ反映していない（[items.md](./items.md)参照）。

## 経験値とレベル成長

- 経験値は敵ごとの基礎値に経験値係数（`expCoefficient`、上記「敵の出現パターン・強さ・背景」参照）をかけて算出。ステータスのステージ係数より緩やかな伸びにしている
- 貯まった経験値は「経験値ポイント」として持ち越され、[キャラクター確認画面](./screens/character-view.md)で好きなキャラクターに任意で割り振ってレベルアップさせる（自動で均等配分はしない）。極振りを防ぐため、レベルごとのHP/攻撃力/防御力は固定テーブル
- 最大レベル100。ステージ100（メインストーリーのゴール、以降はエンドコンテンツ扱い）までに全キャラがレベル100へ届かなくても問題ない前提
- レベル別ステータステーブル（Lv1〜100、キャラ4人分）はArtifact参照。実装は[lib/character-growth.ts](../../lib/character-growth.ts)（旧`lib/characters.ts`の仮ステータス表示は削除し、こちらに一本化した）
- **レベルアップに必要な経験値ポイント**：Artifactでは未定だったため、仮に「Lv→Lv+1に必要なポイント＝10×到達後のレベル」という単純な右肩上がりの式にしている（ユーザー確認済みの仮数値）。実装は[lib/character-growth.ts](../../lib/character-growth.ts)の`expCostForLevel` / `cumulativeExpForLevel` / `levelFromInvestedExp`。セーブデータには「そのキャラにこれまで投入した経験値ポイントの累計」（`Game1SaveData.characterInvestedExp`）だけを持たせ、レベルはそこから逆算する方式にしている（途中経過の端数を失わないため）

## アイテムドロップ

実装: [lib/item-drop.ts](../../lib/item-drop.ts)。

- 通常バトル（s=1〜9）は3%、ボス戦（s=10）は5%の確率でアイテムが1つ落ちる（バトルごとに独立抽選）
- レアリティは、そのステージ番号を10刻みでブロック分けした抽選テーブルに従う（1〜10はCのみ、11以降Bが混じり始め…91〜100でもSSは5%止まり）。テーブルの全数値は`lib/item-drop.ts`の`RARITY_BLOCKS`参照（元はArtifactの「3. アイテムのレアリティ抽選テーブル（案）」）
- レアリティが決まった後、どのアイテムになるかは全アイテムから均等ランダム（武器種問わず。装備できないキャラの武器種のものも出る）
- ステージ全滅時も、そこまでに完全にクリアしたバトル分のドロップは持ち帰れる（全滅した瞬間に戦っていたバトル自体のドロップ抽選はしない）。獲得したアイテムは[戦闘画面](./screens/battle-test.md)のクリア画面（全滅時は敗北画面）に一覧表示され、`Game1SaveData.inventory`に加算される
